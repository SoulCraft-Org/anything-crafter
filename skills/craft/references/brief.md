# Brief

Vision first. Examples second. One round, at most 5 questions.

## 1. Ask the vision interview

First, rule 4: asked to copy a name, logo, text, code or a lock? Open your reply with a one-line no that states the rule and offers an original. Then ask.

Say: "Answer, say yes to take my pick, or say just go."

| # | Ask | Recommended answer |
| --- | --- | --- |
| 1 | What is it, in one sentence? | Say it back in plain words |
| 2 | Who is it for? | One group of people, named |
| 3 | What must it do on day one? | The 1 to 3 smallest things that make it useful |
| 4 | What would make you say "this is mine"? | One thing no example has |
| 5 | What must it never do? | Copy an example's words, art or code |

1. Show the table with a recommended answer filled in for this request.
2. "yes" takes my pick. "just go" takes every pick. Silence means "just go".
3. Never ask a sixth question. Never ask a second round.

## 2. Ask for examples

Ask: "Which examples should I study? Send links, files or names."

| # | Example (link, file or name) | Type (website, web app, code, doc, design, app) | Why it matters |
| --- | --- | --- | --- |
| E1 | | | |

Need 1 or more. None given: say so and wait. Never invent one.

## 3. Fill in `craft/brief.md`

```
# Brief
Date: <yyyy-mm-dd>
Answers: <asked | just go>

## Vision
V1. <what it is>
V2. <who it is for>
V3. <day-one thing>
V4. <what makes it mine>
V5. <what it must never do>

## Examples
E1. <link, file or name> (<type>)

## Promises
P1. <one thing a person can check, from V3>
P2. <one thing a person can check, from V4>
```

| Promise rule | Right | Wrong |
| --- | --- | --- |
| Checkable | "A new person adds a task in 2 clicks" | "It is easy to use" |
| One line, one check | P1 and P2 are separate | "Fast and pretty and safe" |
| Traces to a V-line | P1 comes from V3 | A promise no V-line asked for |
