# Guide: web app

## What this route covers

A web app that runs in the browser, such as a tool, dashboard or editor. You learn its flows, states, data shapes and interactions from its public pages.

## What to look at

1. Open the public entry page and say what the app does in one line.
2. List the flows a visitor can start without an account (a demo, a free tool, a shared link).
3. For each flow, write the steps from the first click to the result.
4. Note each state a screen can be in: empty, loading, filled, error, done.
5. Note the data the person enters and the data they get back, as fields and types.
6. Note the interactions: drag, keyboard shortcuts, undo, auto-save, live updates.
7. Read the data shapes in the page source and in the responses you can see without logging in.

## How to study it

| Case | Do |
| --- | --- |
| Default | Use a browser tool if you have one. Walk each public flow and watch what the page shows |
| Fallback | Fetch the public pages as text and read their source. List what you could not run as Unknown |

Public pages only.

## What to record on the study card

| Part | Write down |
| --- | --- |
| Flows | Each flow as numbered steps |
| States | The states of each key screen |
| Data shapes | Field names, types and examples you saw |
| Interactions | What the person can do, and what happens |
| Proof | The address or screen behind each claim |

Mark each line Seen, Inferred or Unknown. Anything behind a login is Unknown.

## When to say no

Say no, and say why in one line, when:

- A step needs a login, a paywall or a payment. Never get around it.
- You are asked to use someone else's account, token or session.
- You are asked to load-test it or probe it for weak spots.
- You are asked to copy its code, text or brand.
